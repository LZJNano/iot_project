## 1. 项目一句话描述

基于 **本地 MQTT 协议**,在华清远见 FS6818 实验箱上跑 `mqtt_iot` 客户端,通过 Ubuntu VM 上的 Mosquitto broker,实现:
- 实验箱周期性上报温湿度
- 上位机(MQTT 客户端)下发控制指令,实验箱响应

**完全对应任务书"基本要求"**:本地 MQTT 服务器接入 + 传感器数据上报 + 远程控制。

## 2. 系统架构

```
┌────────────────────────────────────────────────────────┐
│  Ubuntu VM (192.168.100.192, 桥接)                      │
│   ├── mosquitto broker(0.15)  :1883                    │
│   ├── /source/rootfs/  (NFS 根)                         │
│   │     └── root/mqtt_iot/mqtt_iot  (ARM 32-bit ELF)   │
│   └── /source/rootfs/lib/modules/3.4.39-farsight/extra/ │
│         └── dht11.ko (built-in, 自动 probe)              │
│                                                        │
│  ↑ 网线                                                │
│                                                        │
│  FS6818 实验箱 (192.168.100.111)                        │
│   ├── uboot 启动从 VM NFS 挂根                          │
│   ├── /dev/dht11 由 mqtt_iot 自动 mknod                 │
│   ├── /sys/class/leds/led{1..4}/brightness             │
│   └── /dev/fb0  LCD framebuffer                        │
└────────────────────────────────────────────────────────┘

控制流:PC 终端 → mosquitto_pub → broker → 实验箱 mqtt_iot 订阅 → 操作 LED/LCD
数据流:实验箱 mqtt_iot → DHT11 读 → mosquitto_publish → broker → PC 终端 mosquitto_sub
```

## 3. 实际可演示的功能

| # | 设备 | 命令 | 现象 |

**说明**:
- 板子上只有 4 个 LED,`led5_on` 等命令静默拒绝(日志不报错)
- **舵机实测可用**,出厂镜像自带驱动(/dev/servo 自动注册),5 档预设 + 任意角度
- 蜂鸣器在源码里实现为应用层 + 占位逻辑,rootfs 上没装 beep.ko,`beep_on/off` 命令只打 LOG_W,不影响答辩
- 如果想真让蜂鸣器响,需要交叉编译 `6818M4/beep_driver.c + pwm_timer.c` 得到 beep.ko,push 到 rootfs,insmod,mknod(主 10,minor 从 /proc/misc 查)

## 6. 启动顺序(完整流程)

1. **VM 启动**,mosquitto 自动运行,`/source/rootfs` 准备好
2. **实验箱上电**,uboot 倒计时按任意键进 uboot
3. **执行 uboot 命令**(已固化到环境变量,这里给出参考):
   ```
   setenv bootcmd ext4load mmc 2:1 0x48000000 uImage\;bootm 0x48000000
   setenv bootargs root=/dev/nfs nfsroot=192.168.100.192:/source/rootfs,proto=tcp console=ttySAC0,115200 init=/linuxrc ip=192.168.100.111:::::eth0:off
   saveenv
   boot
   ```
4. **实验箱进 Linux**,NFS 根挂上,串口看到 `mount` 列出 NFS
5. **直接跑** `cd /root/mqtt_iot && ./mqtt_iot 192.168.100.192`
6. **日志显示**:
   ```
   [INFO] ===== mqtt_iot starting, broker=192.168.100.192 =====
   [INFO] LED: opened 4/4 sysfs nodes
   [INFO] LCD 1024x600, 32bpp
   [INFO] DHT11: opened /dev/dht11
   [INFO] MQTT connected to 192.168.100.192:1883
   [INFO] subscribed to s5p6818/device/ctrl
   [INFO] publish s5p6818/env/data: {"hum":0,"temperature":0}
   ```

## 8. 答辩可能被问到的问题(预演)

**Q:为什么不用阿里云?**
A:本项目选择本地 MQTT 方案,优点是部署简单、延迟低、不依赖外网;参考 `docs/参考资料/本地MQTT应用参考.md`。云平台方案在 `docs/参考资料/云平台IOT开发.md` 有完整文档,如果需要可以扩展。

**Q:数据安全吗?**
A:本项目用 Mosquitto 默认的 `allow_anonymous`,适合局域网演示;实际部署可以加用户认证、TLS 加密。

**Q:DHT11 数据为什么是 0?**
A:板子上的 DHT11 模块没接,`read()` 阻塞在驱动里(因为驱动要做单线协议时序),5s 后 publish 一次,值为 0 是预期行为。

**Q:为什么用 NFS 根而不是本地文件系统?**
A:开发阶段方便,NFS 改完代码直接生效,不用烧写 eMMC;生产环境烧到 eMMC 启动更可靠(任务书 uboot 命令里 `ext4load mmc 2:1` 就是从 eMMC 加载内核)。

**Q:RPC 怎么实现的?**
A:不是 RPC,是 MQTT pub/sub 模式。broker 收到 `s5p6818/device/ctrl` 主题的消息,转发给订阅该主题的实验箱 mqtt_iot,实验箱解析 payload 字符串执行对应动作。

**Q:为什么不直接用 HTTP / WebSocket?**
A:MQTT 是 pub/sub 模型,适合"一对多"消息分发,broker 解耦生产者和消费者;HTTP 是请求-响应,需要客户端主动拉。物联网场景下设备状态变化频繁,pub/sub 更合适。
