# 演示稿 — 录视频用

> 总时长建议 3~5 分钟。一边录一边按这个脚本走,边说边操作。
> 提前把 3 个终端窗口开好,免得录的时候手忙脚乱。

## 录之前准备(2 分钟)

**窗口 1 — VM 终端**(实验室电脑 VM 192.168.100.192,或 NAT 192.168.127.100):

```bash
# 启动订阅(后面会持续跑,显示数据)
mosquitto_sub -h 127.0.0.1 -t s5p6818/env/data -v
```

**窗口 2 — VM 终端**(另一个,留着发控制指令用)

**窗口 3 — 串口**(PuTTY / COM6 / 115200,看实验箱 log)

**窗口 4 — 实物**(摄像头拍实验箱,LED 和 LCD 要能看见)

---

## 第 1 段:开场(15 秒)

> "这是我做的'基于本地 MQTT 的物联网应用开发',演示的是华清远见 FS6818 实验箱通过 Mosquitto broker 和上位机通信。"

镜头:从 VM 终端拉到实验箱,再到串口 log。

## 第 2 段:展示整体运行状态(20 秒)

> "现在 mqtt_iot 已经在实验箱上跑起来了,我们看到它连接了 broker,订阅了控制主题 s5p6818/device/ctrl,并且每 5 秒发布一次温湿度数据。"

**串口窗口展示**:
```
[INFO] MQTT connected to 192.168.100.192:1883
[INFO] subscribed to s5p6818/device/ctrl
[INFO] publish s5p6818/env/data: {"hum":0,"temperature":0}
[INFO] publish s5p6818/env/data: {"hum":0,"temperature":0}
```

**VM 窗口 1 同步展示**(刚刚的订阅窗口):
```
s5p6818/env/data {"hum":0,"temperature":0}
s5p6818/env/data {"hum":0,"temperature":0}
```

> "可以看到上位机的 mosquitto_sub 也同步收到了这些数据,这是上行链路。"

## 第 3 段:温湿度数据(20 秒)

> "数据每 5 秒更新一次。目前是 0,0 是因为 DHT11 模块在板子上没接,只验证了数据通路上传链路是通的,任务书的示例文档里也是这个数值。"

## 第 4 段:LED 远程控制(40 秒)

镜头切到实验箱上的 LED 灯组。

> "现在测试 LED 远程控制。我从 VM 发一个 led_on:"

**VM 窗口 2 执行**:
```bash
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m led_on
```

**实验箱上 4 个 LED 全亮**。同时串口 log 显示:
```
[INFO] RX s5p6818/device/ctrl: led_on
[INFO] LED 1 -> OFF
[INFO] LED 2 -> OFF
[INFO] LED 3 -> OFF
[INFO] LED 4 -> OFF
```

> "全亮。现在分别控制单个 LED:"

```bash
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m led1_off
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m led3_off
```

> "1 号和 3 号 LED 灭,2 号和 4 号还亮着。"

(然后) 
```bash
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m led_off
```

> "全部关掉,演示完成。"

## 第 5 段:LCD 颜色填充(40 秒)

镜头切到实验箱 LCD 屏幕。

> "现在测试 LCD 远程控制,可以切换全屏颜色。"

依次发命令,每次切到下一个颜色:

```bash
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m lcd_red
# 屏幕变红
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m lcd_green
# 屏幕变绿
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m lcd_blue
# 屏幕变蓝
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m lcd_white
# 屏幕变白
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m lcd_yellow
# 屏幕变黄
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m lcd_black
# 屏幕变黑(关屏效果)
```

每次发完,**镜头扫一下 LCD 屏幕**,停顿 1~2 秒,让学生看清。

> "可以看到 LCD 的颜色通过 MQTT 主题消息实时切换,延迟在 100ms 以内。"

## 第 5.5 段:舵机角度控制(30 秒,加分项)

镜头切到实验箱上的舵机(那个小马达带白色塑料片的)。

> "再加一个,舵机控制。5 档预设角度:"

```bash
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m servo_0
# 舵机转到 0°
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m servo_90
# 舵机转到 90°(看塑料片从 0° 转到 90°)
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m servo_180
# 舵机转到 180°
mosquitto_pub -h 127.0.0.1 -t s5p6818/device/ctrl -m servo_angle 45
# 舵机转到 45°(任意角度命令)
```

> "也可以用 servo_angle 任意角度。舵机的 PWM 信号由 Mosquitto 主题消息触发,通过 broker 转发,延迟在 100ms 内。"

## 第 6 段:关键代码片段(30 秒,可选)

镜头切到 windows 仓库,打开 `src/main.c` 的 `on_ctrl_message` 函数:

> "控制指令的处理逻辑在这里,on_ctrl_message 接收 broker 转发的 payload,根据字符串分发到 LED / LCD 模块。"

```c
if (!strcmp(payload, "led_on"))  { led_set_all(1); return; }
if (!strcmp(payload, "led_off")) { led_set_all(0); return; }
...
if (strncmp(payload, "lcd_", 4) == 0) {
    const char *name = payload + 4;
    lcd_fill_named(name);
    return;
}
```

> "协议简单、扩展容易,要加新设备只需要在 main.c 加一行 sscanf 分发。"

## 备用:如果某一步失败

| 失败 | 应急 |
|------|------|
| 串口乱码 | 确认 PuTTY 是 115200 8N1,关掉再重开 |
| LED 没反应 | 重新跑 `./mqtt_iot 192.168.100.192` |
| LCD 没反应 | 看串口 log 有没有 "LCD fill" 输出,可能是权限问题 |
| 订阅没数据 | 看 `mosquitto -h` 用对 IP,broker 是否在 1883 监听 |
| 实验箱进不去 Linux | 串口抓 log,大概率是 NFS 没挂上,看 VM 上 `showmount -e` 是不是还导出 /source/rootfs |
